# Maven Build Lifecycle

## 1. What Is the Maven Build Lifecycle?

The Maven Build Lifecycle is a sequence of steps that Maven follows to build and manage a project.

It defines how tasks such as validating the project, compiling code, running tests, packaging the application, and installing the final artifact are performed.

Maven provides three built-in lifecycles:

1. Default Lifecycle
2. Clean Lifecycle
3. Site Lifecycle

## 2. Default Lifecycle

The Default Lifecycle manages the main process of building and deploying a project.

Important phases include:

| Phase | Purpose |
|---|---|
| `validate` | Checks whether the project is configured correctly. |
| `compile` | Compiles the main source code. |
| `test` | Runs tests using the configured test framework. |
| `package` | Packages the compiled application, such as into a JAR or WAR. |
| `verify` | Performs checks on the packaged result. |
| `install` | Installs the artifact into the local Maven repository. |
| `deploy` | Publishes the artifact to a configured remote repository. |

These phases run in order when a later phase is requested.

For example, executing `mvn package` runs the required earlier phases before packaging.

## 3. Clean Lifecycle

The Clean Lifecycle removes files generated by previous builds.

Its main phases are:

- `pre-clean`: Executes tasks before cleaning.
- `clean`: Removes generated build output, usually the `target` directory.
- `post-clean`: Executes tasks after cleaning.

Example command:

```bash
mvn clean
```

This removes generated build output. It does not delete source files in `src`.

## 4. Site Lifecycle

The Site Lifecycle generates and manages project documentation.

Its main phases are:

- `pre-site`: Executes tasks before generating the site.
- `site`: Generates project documentation.
- `post-site`: Executes tasks after generating the site.
- `site-deploy`: Publishes the generated site to a configured location.

This lifecycle is useful when a project needs generated documentation.

## 5. How Does Maven Execute Phases?

Suppose we run:

```bash
mvn package
```

Maven executes the required phases of the Default Lifecycle up to `package`.

A simplified flow is:

```text
validate
   ↓
compile
   ↓
test
   ↓
package
```

The actual lifecycle contains additional phases, and plugins may bind goals to different phases.

We do not normally need to run every phase separately.

## 6. What Is a Plugin Goal?

A plugin goal performs a specific task.

Examples include:

- Compiling Java code.
- Running unit tests.
- Creating a JAR file.
- Generating project documentation.

Maven plugins connect these tasks to lifecycle phases.

For example, the Maven Compiler Plugin provides compilation goals, while the Maven Surefire Plugin runs tests.

A lifecycle phase may invoke one or more plugin goals.

## 7. Difference Between Lifecycle, Phase, and Goal

| Term | Meaning |
|---|---|
| Lifecycle | A complete sequence of build stages. |
| Phase | One stage within a lifecycle. |
| Goal | A specific task performed by a plugin. |

Example:

- Lifecycle: Default Lifecycle
- Phase: `compile`
- Goal: `compiler:compile`

Remember that a phase and a goal are related, but they are not the same thing.

## 8. Common Maven Commands

### Clean the project

```bash
mvn clean
```

Removes generated build output.

### Compile the project

```bash
mvn compile
```

Compiles the main Java source code.

### Run tests

```bash
mvn test
```

Runs tests after the required earlier build phases.

### Package the project

```bash
mvn package
```

Builds and packages the application.

### Install the artifact locally

```bash
mvn install
```

Builds the project and installs its artifact in the local Maven repository.

### Clean and package

```bash
mvn clean package
```

Cleans previous output and then executes the build through the `package` phase.

## 9. Practical Example

Suppose a project contains:

```text
MavenLearning/
├── pom.xml
└── src/
    └── main/
        └── java/
            └── Main.java
```

Open the terminal in the `MavenLearning` directory.

First, run:

```bash
mvn clean
```

Next, compile the code:

```bash
mvn compile
```

Finally, package the project:

```bash
mvn package
```

If the build succeeds, generated files and the configured package will generally be available in the `target` directory.

The exact output depends on the project's POM and build plugins.

## 10. Key Takeaways

- Maven has three built-in lifecycles: Default, Clean, and Site.
- The Default Lifecycle handles the main build process.
- The Clean Lifecycle removes generated build output.
- The Site Lifecycle generates project documentation.
- A phase is a stage in a lifecycle.
- A goal is a specific task performed by a plugin.
- Running a later phase executes the required earlier phases in that lifecycle.

Understanding the Maven Build Lifecycle helps developers build, test, and package Java applications consistently.
